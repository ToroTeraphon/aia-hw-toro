ผู้เรียนต้องการบันทึกงานรอบนี้ ทำตามขั้นตอนต่อไปนี้ทีละข้อ ห้ามข้าม

สิ่งที่ผู้เรียนพิมพ์มาเพิ่ม (ถ้ามี): $ARGUMENTS

1. **ดูว่าเปลี่ยนอะไรไป:** รัน `git status` และ `git diff` ถ้าไม่มีอะไรเปลี่ยนเลย ให้บอกผู้เรียนแล้วหยุด

2. **ตรวจความปลอดภัยก่อน:** ไล่ดูทุกไฟล์ที่เปลี่ยนหรือเพิ่มใหม่ ถ้าเจอสิ่งใดต่อไปนี้ ให้หยุด บอกผู้เรียนว่าเจออะไรในไฟล์ไหน และห้าม commit จนกว่าจะเอาออก
   - API key, password, token, ไฟล์ `.env`
   - ข้อมูลพอร์ตจริง จำนวนหุ้น เลขบัญชี ข้อมูลส่วนตัว
   - ไฟล์ข้อมูลดิบที่ซื้อมา เช่น SETSMART หรือบทวิเคราะห์โบรกเกอร์

3. **หาเลขรอบ:** เปิด `prompts.md` ถ้าหัวข้อ "รอบ 1" ยังเป็นแบบฟอร์มว่าง (มีวงเล็บเหลี่ยม `[ ]` อยู่) ให้เขียนลงรอบ 1 แทนที่แบบฟอร์ม ถ้ามีรอบที่เขียนแล้ว ให้ใช้เลขถัดไปต่อท้ายไฟล์ และลบแบบฟอร์มว่างที่เหลือออก

4. **เขียนบันทึกขั้นตอนใน `prompts.md`** ให้ครบทุกช่องตามแบบฟอร์ม:
   - **ทำอะไร:** จากสิ่งที่เปลี่ยนในข้อ 1 และสิ่งที่ผู้เรียนพิมพ์มา
   - **เครื่องมือ / model:** ชื่อ AI และ model ที่ใช้ในรอบนี้
   - **Prompt ที่ใช้:** คัดลอก prompt หลักที่ผู้เรียนพิมพ์ในรอบนี้มาตามจริง ห้ามแต่งใหม่ ถ้ามีหลาย prompt ให้ใส่อันที่สำคัญที่สุด 1–3 อัน
   - **ผลที่ได้:** ได้อะไร ดีตรงไหน ยังขาดอะไร
   - **ตัดสินใจอะไร และเพราะอะไร:** ถ้าไม่รู้เหตุผลจริง ให้ถามผู้เรียน 1 คำถามสั้น ๆ ก่อนเขียน ห้ามเดาเหตุผลแทน
   - **ขั้นต่อไป:** รอบหน้าจะทำอะไร

5. **บันทึกบทเรียนใน `PROJECT_MEMORY.md`:** ถ้ารอบนี้เจอ error ผลผิด หรือลองวิธีที่ไม่เวิร์ก ให้เพิ่มในหัวข้อ "บันทึกปัญหา" ว่าเจออะไร สาเหตุ แก้อย่างไร ถ้าบทเรียนควรจำไว้ใช้ต่อ ให้เขียนเป็นกฎ 1 บรรทัดในหัวข้อ "กฎที่ได้จากบทเรียน" ถ้าไม่มีปัญหาเลย ข้ามข้อนี้ได้

6. **วัดการใช้ทรัพยากร:** ทำหลังเขียน `prompts.md` เสร็จและก่อน commit เพื่อให้แถวใหม่เข้า commit เดียวกับรอบนี้ ทำตามกฎ "วัดการใช้ทรัพยากรทุกครั้งที่ /save" ใน `PROJECT_MEMORY.md`
   - เรียกเครื่องมือ `get_usage` หนึ่งครั้ง แล้วเพิ่ม 1 แถวต่อท้ายตารางใน `usage_log.md` (ถ้าไฟล์ยังไม่มี ให้สร้างพร้อมหัวตาราง)
   - คอลัมน์: รอบ, วันที่, 5h %, Weekly %, Messages, ส่วนคงที่ (ทุกอย่างที่ไม่ใช่ Messages), รวม แล้วตามด้วยผลต่างจากแถวก่อน (Δ 5h, Δ Messages, Δ ส่วนคงที่) และหมายเหตุ
   - แตกส่วนคงที่เป็นรายหมวดเฉพาะหมวดที่เปลี่ยน ≥ 5,000 tokens จากแถวก่อน (ใส่ในหมายเหตุพร้อมคำว่า "เปลี่ยนตามชุดเครื่องมือ ไม่ใช่ตามงาน") ถ้าเปลี่ยนน้อยกว่านั้นไม่ต้องแยก
   - Δ 5h น้อยกว่า 1% ให้เขียน `<1%` (ต่ำกว่าความละเอียดของเครื่องมือ) รายงานต้นทุนเป็น % ของโควต้าเท่านั้น ห้ามแปลงเป็นเงิน
   - ถ้า Messages ต่ำกว่าแถวก่อน แปลว่ามีการ compact ให้ใส่ "หลัง compact" ในหมายเหตุ และไม่นับเป็นการใช้
   - ถ้า Messages เกิน 250,000 tokens ให้เตือนผู้เรียนในข้อ 9 ว่าควรสั่ง `/compact` พร้อมคำสั่ง "สรุปทุกการตัดสินใจ และเหตุผลไว้"
   - ถ้าเรียก `get_usage` ไม่ได้ ให้ใส่ "วัดไม่ได้" ในแถวนั้นแล้วทำต่อ ห้ามให้การวัดขวางการ save
   - ในไฟล์ใส่แต่ตัวเลข ห้ามใส่อีเมลหรือข้อมูลบัญชี

7. **commit:** รัน `python scripts/check_secrets.py` ก่อน (ถ้าเจอ FAIL ให้หยุด) แล้ว `git add -A` และ commit ด้วยข้อความภาษาไทยแบบ `รอบ N: ทำอะไร` (สั้น ไม่เกิน 1 บรรทัด)

8. **push:** รัน `python scripts/check_secrets.py --unpushed` ก่อน (ถ้าเจอ FAIL ให้หยุด) แล้วรัน `git push` ถ้ามีหน้าต่างให้ล็อกอิน GitHub ให้บอกผู้เรียนล็อกอินในหน้าต่างนั้น ถ้า push ไม่ผ่าน ให้บอกข้อความ error สั้น ๆ และแนะนำให้เรียกผู้ช่วยสอน

9. **สรุปให้ผู้เรียน:** 3 บรรทัดแรก: บันทึกรอบที่เท่าไร, commit ว่าอะไร, push สำเร็จหรือยัง พร้อมลิงก์ repo บน GitHub แล้วต่อด้วย **สองบรรทัดสั้น ๆ แยกกัน** จากข้อ 6 คือ `โควต้า 5 ชม.: 20% (+2%) รีเซ็ต 2 ชม.` และ `Messages Usage: 77% จากเป้า 250k` (ตัวเลขเต็มและผลต่างอยู่ใน `usage_log.md` แล้ว ไม่ต้องอธิบายซ้ำ) ถ้า Messages เกิน 250,000 tokens ให้เปลี่ยนเป็นคำเตือนสั้น ๆ ว่าควร `/compact` ถ้าส่วนคงที่เปลี่ยน ≥ 5,000 tokens ให้เพิ่มสั้น ๆ ว่าเปลี่ยนเพราะชุดเครื่องมือ
