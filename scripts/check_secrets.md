# check_secrets: ตรวจ secret ก่อน commit และก่อน push

repo นี้เป็น Public ห้ามมี API key, password, token, อีเมลหรือข้อมูลส่วนตัว, ข้อมูลพอร์ตจริง และข้อมูลที่ซื้อมา (เช่น SETSMART) สคริปต์ [check_secrets.py](check_secrets.py) ตรวจส่วนที่ตรวจด้วยเครื่องได้ ในคำสั่งเดียว แทนการที่ AI เขียน `grep` เองใหม่ทุกรอบ

## วิธีใช้

| ใช้เมื่อไร | คำสั่ง | ตรวจอะไร |
|---|---|---|
| **ก่อน commit** (ทุกรอบ) | `python scripts/check_secrets.py` | ไฟล์ที่ `git add -A` จะเพิ่มเข้า commit ถัดไป (แก้ไข + ใหม่ + ที่ stage ไว้) |
| **ก่อน push** | `python scripts/check_secrets.py --unpushed` | บรรทัดที่เพิ่มในทุก commit ที่ยังไม่ถูก push (`origin/main..HEAD`) |
| ตรวจย้อนหลังทั้ง repo | `python scripts/check_secrets.py --history` | บรรทัดที่เพิ่มในทุก commit ของทุก branch |
| ตรวจไฟล์ทั้งหมดตอนนี้ | `python scripts/check_secrets.py --all-files` | ทุกไฟล์ที่ track อยู่ |

- **FAIL** = เจอสิ่งที่ห้ามขึ้น สคริปต์จบด้วย exit code 1 ห้าม commit หรือ push จนกว่าจะแก้
- **WARN** = ควรดูด้วยตา ไม่บล็อก (เช่น เลข 13 หลักที่อาจเป็นเลขบัตรประชาชน, ไฟล์ใหญ่เกิน 5 MB)
- สคริปต์ไม่พิมพ์ค่าที่เจอเต็ม ๆ (ปิดบังส่วนท้าย) เพื่อไม่ให้ secret ไปโผล่บนจอหรือใน log
- ทำไมต้องมีโหมด `--unpushed`: ถ้าใส่ secret ไว้ใน commit หนึ่งแล้วลบออกใน commit ถัดไป ประวัติยังเก็บของเดิม โหมดนี้อ่านทุก commit จึงยังจับได้

## สิ่งที่ตรวจ

- **รูปแบบ key:** `sk-...` (OpenAI/Anthropic), GitHub token (`ghp_`, `github_pat_`), AWS (`AKIA...`), Google (`AIza...`), Slack (`xox...`), private key block
- **การกำหนดค่า:** `api_key = ...`, `secret = ...`, `token = ...`, `password = ...` ที่ค่ายาวตั้งแต่ 12 ตัวอักษร (ข้อความเตือนอย่าง "ห้ามใส่ API key" ไม่ถูกจับ เพราะไม่มีเครื่องหมาย `=` และค่า)
- **อีเมล:** ทุกที่อยู่อีเมล ยกเว้น `@example.com`, `@example.org`, `users.noreply.github.com` และ `noreply@...` (ใส่อีเมลจริงของตัวเองลง repo นี้ไม่ได้เลย)
- **ชื่อไฟล์ที่ห้ามขึ้น:** `.env`, `.env.*`, `*.pem`, `*.key`, `*.p12`, `*.pfx`, `credentials*`, `secrets*`, `*token*`, `*SETSMART*`, `private/`, `data/private/`, `data/raw/`
- **WARN:** เลข 13 หลักติดกัน, ไฟล์ใหญ่เกิน 5 MB

## สิ่งที่ตรวจไม่ได้ (ต้องดูเนื้อหาเอง)

- **ข้อมูลส่วนตัวที่เป็นข้อความธรรมดา:** เช่น จำนวนหุ้นในพอร์ต เลขบัญชี ชื่อ-ที่อยู่ ไม่มีรูปแบบตายตัวให้เครื่องจับ สคริปต์จะบอกเตือนนี้ทุกครั้งที่ผ่าน
- **บทวิเคราะห์โบรกเกอร์และข้อมูลที่ซื้อมา:** จับได้เฉพาะจากชื่อไฟล์ ถ้าคัดลอกเนื้อหามาวางในไฟล์ .md สคริปต์ไม่รู้
- **key ที่หน้าตาไม่ตรงรูปแบบ:** เช่น key ของบริการที่ไม่ได้ใส่ไว้ในรายการ

## ถ้าเจอ FAIL

**ยังไม่ได้ push (แก้ได้โดยไม่มีใครเห็น):**

| กรณี | วิธี |
|---|---|
| ยังไม่ commit (เจอจาก `--commit`) | ลบข้อความออกจากไฟล์ แล้วรันตรวจใหม่ |
| อยู่ใน commit **ล่าสุด** | ลบข้อความออกจากไฟล์ แล้ว `git commit --amend` |
| อยู่ใน commit **เก่ากว่า** ที่ยังไม่ push | `git reset --mixed origin/main` (ไฟล์ในเครื่องยังอยู่ครบ) แก้ไฟล์ แล้ว commit ใหม่เป็นรอบ ๆ |
| เป็นไฟล์ที่ไม่ควรขึ้นเลย | `git rm --cached ไฟล์` แล้ว amend หรือ reset ตามข้างบน และเพิ่มชื่อใน `.gitignore` |

- อย่าแก้ด้วยการ commit ลบทับ แล้ว push ทั้งหมดขึ้นไป ข้อความเดิมจะยังอยู่ใน commit เก่าและเปิดดูได้
- ล้างร่องรอยในเครื่อง: `git reflog expire --expire=now --all` แล้ว `git gc --prune=now`
- ใช้ `git log -S"ข้อความ" origin/main..HEAD` หาว่า commit ไหนใส่ข้อความนั้นเข้ามา
- AI ไม่แก้ประวัติ git เองโดยไม่ถามก่อน (`reset` และ `amend` เขียนทับ commit เดิม)

**push ไปแล้ว:** **เปลี่ยน key ใหม่ก่อนเป็นอย่างแรก** การลบไฟล์หรือเขียนประวัติทับแล้ว force push ไม่พอ เพราะมีคนอื่นอาจคัดลอกไปแล้ว และ GitHub อาจยังเก็บ commit เดิมให้เปิดดูด้วยลิงก์ตรง ถ้าเป็นข้อมูลส่วนตัว (ไม่ใช่ key) ให้ลบให้เร็วที่สุดและแจ้งผู้สอน

## ขั้นตอนเดิมที่ทำด้วยมือก่อนมีสคริปต์ (สิ่งที่สคริปต์แทน)

ก่อนมีสคริปต์นี้ AI ตรวจก่อน commit ด้วยขั้นตอนต่อไปนี้ ซึ่งตรวจได้ไม่สม่ำเสมอ เพราะเขียนคำสั่งใหม่ทุกรอบ และบางรอบ grep เฉพาะไฟล์ที่เปลี่ยน บางรอบ grep ทั้ง repo

1. `git status` และ `git diff --stat` ดูว่าไฟล์ไหนเปลี่ยน
2. `grep -ciE "<อีเมลของผู้เรียน>|api[_-]?key|password|secret"` ในไฟล์ที่เปลี่ยนหรือที่ track ทั้งหมด
3. ถ้าเจอคำในข้อความ (เช่น คำเตือนในไฟล์ของคอร์ส) เปิดดูว่าเป็นข้อความเตือนหรือค่าจริง
4. ตรวจย้อนหลังเมื่อถูกถาม: `git log --all -S"<อีเมล>"` กับ `git log --all -G"<รูปแบบ key>"` และ `git ls-files | grep -iE "\.env|\.pem|\.key|data/raw|setsmart|credentials|secret"`
5. อ่านเนื้อหาไฟล์ที่เปลี่ยน (ทำจริงเฉพาะไฟล์ขนาดเล็ก ไฟล์ CSV ใหญ่อาศัย grep)

ข้อเสียที่ทำให้ต้องเขียนสคริปต์: ขั้น 2 และ 4 ต้องมีอีเมลจริงของผู้เรียนในคำสั่ง ซึ่งไม่ควรเขียนลงไฟล์ใน repo สคริปต์ใช้การตรวจ "ทุกอีเมล" แทน จึงไม่ต้องรู้อีเมลของใคร

## สถานะการใช้งาน

- **ตอนนี้:** AI รัน `python scripts/check_secrets.py` ก่อน commit ทุกครั้ง แทนการ grep เอง (กฎอยู่ใน `PROJECT_MEMORY.md`) และรัน `--unpushed` ก่อน push
- **ยังไม่ได้ทำ:** ผูกกับ pre-push hook, แก้ `.claude/commands/save.md`, `AGENTS.md` และ README ตามข้อเสนอใน `PROJECT_MEMORY.md` รอผู้เรียนสั่ง
- **ทดสอบแล้ว:** ผ่านกับ repo จริงทั้ง 4 โหมด (FAIL 0 · WARN 0) และทดสอบการจับใน repo ทดลองแยกต่างหาก: key ที่ถูกลบทับใน commit ถัดไปยังจับได้ด้วย `--unpushed`, อีเมล, `password = ...`, ไฟล์ `.env`, ไฟล์ `secrets*` และเลข 13 หลัก ส่วน `you@example.com` ไม่ถูกจับตามที่ตั้งไว้
